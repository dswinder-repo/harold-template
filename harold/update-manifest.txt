# Harold-owned machinery: the files `bin/harold update` keeps in step with the starter.
#
# Everything else in the workspace is the operator's and is never touched: the vault (except its templates),
# memory/, dashboard/, raw/, projects/, and Harold's data files (learnings, blockers, alerts, events, facts,
# projects.md, the CRM queue, the trigger log, briefs, session files, settings.env, upstream.json). AGENTS.md is
# the operator's own too: when the starter's changes, update writes AGENTS.md.upstream beside it to merge by hand.
#
# A machinery file edited in the workspace is never overwritten: the starter's copy is written next to it as
# <file>.upstream and listed, for a session to merge. To keep a path out of updates in one workspace, list it in
# "skip" in harold/upstream.json (e.g. "skip": ["tools/harold-crm/"]).
#
# Syntax: one path per line; a trailing / means everything under that directory; * and ** are globs.
#   seed <path>    added when missing, then the operator's (never updated)
#   ! <pattern>    excluded
# This file updates itself first: the starter's copy decides what the starter owns.
